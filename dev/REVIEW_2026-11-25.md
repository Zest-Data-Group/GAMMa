## 4. Optimisation

### 4.1 Land clip dominates the gap analysis (biggest win)

`run_gap_analysis()` clips every record's buffer to land one by one
(`terra::intersect(v_buffer, land_proj)`, `R/gap_analysis_functions.R:415`).
At 1,000 records that one call is 2.95 s of a 3.57 s run. Dissolving the
buffers by type first and clipping the two resulting polygons took 0.06 s and
gave the same area to 3 parts in a million (1,127,740 vs 1,127,743 km²).

| Records | Buffer method now | Hull method now |
|---|---|---|
| 200 | 0.7 to 1.0 s | 0.7 to 1.1 s |
| 1,000 | 3.4 s | 3.3 s |
| 3,000 | 9.6 s | 9.2 s |

This is a prototype number, not a tested change. The dissolve also replaces the
later `group_by` + `st_union` that builds `sf_buffers`. The GRS goldens should
stay inside the 1e-4 tolerance but need a run to confirm.

### 4.2 Long work blocks every user on the process

GBIF downloads and the gap analysis run synchronously. Advanced mode can ask
for up to 2,000 records twice at 300 per page, with no timeout (M-3). On one R
process, every other session waits. Options, cheapest first:

1. Add the timeouts (M-3). Required regardless.
2. Run more than one R process per instance on the host.
3. Move `gbif_gather()` and `run_gap_analysis()` into `shiny::ExtendedTask`.
   Both are already pure functions, which makes this practical.

I did not time live GBIF calls; do that as part of the load test.

### 4.3 Smaller items

- `gbif_counts()` makes three sequential requests each time a taxon resolves.
  One request with a `basisOfRecord` facet would replace two of them.
- Start-up is 4.2 s and about 230 MB of R heap before any session; the heap
  peaked near 590 MB after several analyses and reports. Check this against
  the instance size during the load test.
- The taxonomy dataset is opened and the 26,591 genera listed once per
  session (0.16 s). Moving both to `global.R` is trivial and removes
  per-session work.
- Report rendering is fine: 1.1 s and 1.0 MB at 200 records, 1.3 s and 1.5 MB
  at 1,000.
- `.Rprofile`, renv and `rmapshaper` (attached at start-up, used only in the
  report) are worth a look only if start-up time matters on the host.

## 5. Code clarity

Ordered by how much future bug risk each removes.

1. **Draw the gap map once.** The app (`R/module_gap_analysis.R:229-275`) and
   the report (`reportTemplate.Rmd:176-273`) each build the same layers and
   palettes by hand. M-11 and M-14 both come from the two copies drifting.
   One `add_gap_layers(map, res)` plus one `gap_palettes()` used by both
   removes that class of bug.
2. **Split `R/module_controls.R` (848 lines).** It holds the taxon picker, the
   GBIF gather, the upload flow, the export and the format modal. Three
   modules (taxon picker, GBIF, upload) would each fit on a screen and the
   overwrite/confirm state machines (M-7, M-8) become testable alone.
3. **One coordinate filter.** "As numeric, drop NA lat/lon" is written five
   times (`prep_lat_lon()`, `render_base_points()`,
   `update_selection_highlights()`, the polygon select in `module_map.R`,
   `fit_map_to_points()`). `prep_lat_lon()` already exists.
4. **One colour lookup.** The source x type colour `case_when` is duplicated
   in `module_dt_table.R:33` and `leaflet_maps.R:203`.
5. **Config in one place.** `exists("APP_VERSION")`-style fallbacks appear
   13 times across `utils.R` (11), `report_render.R` and
   `module_gap_analysis.R`.
   A single `app_config()` list with defaults removes them.
6. **Dead code.** `generateCounts()` tests numeric columns against `"\\N"`,
   `""` and `"NULL"` and calls `!is.null()` on a column; the `random`
   argument in `gbif_select_records()` and `gbif_gather()` is unused
   backwards compatibility; the two `replace_na` lines in the report.
7. **Inline JavaScript and CSS.** The WDPA identify handler, the About page
   table of contents and the DT link renderer are JS inside R strings, and
   several panels carry inline `style=`. Moving them to `www/` makes them
   lintable and keeps R files readable.
8. **Duplicate outputs.** `row_count_gbif` and `row_count_upload` in
   `module_data_analysis.R` are the same 15 lines twice.
9. **Style.** `%>%` and `|>` are mixed within single functions, and attached
   versus `pkg::` calls are mixed. Pick one per file when touching it.
10. **Provenance.** The README notes that the build scripts for
    `plant_taxonomy_lean.parquet` and `ecoregionsSimplified.gpkg` are not in
    the repo. Add them to `preprocessing/` before release so the layers are
    reproducible.
